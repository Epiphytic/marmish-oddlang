# Basic-command reference preflight

The companion needs a control in which upstream peers run a fixed corpus through a test-owned relay. The reference pin is `af54339d250290490d62d4475a77539b7e739071`.

## Fixture contract

The short fixture is the executable `verification/whole/basic-command-interop/corpus.py`. Run it from its owning server workspace with a fixed case name and a lowercase 64-character hex nonce. Each case pins stdin, stdout and stderr as byte literals and an exit status. The private working directory, credential sandbox and clean environment come from the runner. The cases cover separate streams, empty output, exact trailing bytes and an intentional nonzero exit.

The finite fixture is the native Cargo binary `marmish-installed-fixture` from the pinned `marmish-native` crate, enabled by `installed-checks`. It follows the byte formulas in [upstream installed_fixture.rs](https://github.com/Epiphytic/marmish/blob/af54339d250290490d62d4475a77539b7e739071/crates/marmish-native/src/installed_fixture.rs), source SHA-256 `50cf2a2e6acd5e0470351dbda93c4e76583efef8622d1d0d9e9cef5e010e19a2`. It consumes 16,384 bytes, produces two 131,072-byte streams and exits 7. The finite detached CLI flow submits the fixture and waits separately. The corpus fixes vector 0 and a four-value nonce schedule.

Pass byte-valued argv. The first entry must be the executable's canonical absolute path. The other six entries are the 64-byte lowercase nonce, ASCII `0`, the empty byte string, the quoting probe, the UTF-8 line-break probe and the byte sequence `65 ff 64`, exactly as represented in `finite_case`. Send the pinned input followed by EOF. Use a new mode-0700 `receipts` directory beside the executable, drain both streams concurrently and enforce a 330-second deadline. Compare every receipt field, including the digest of length-prefixed argv and the executable digest. The fixture publishes each nonce receipt once. The direct replay checks all five short cases and four finite payloads. Mutation checks reject a wrong vector, stream or exit status.

## Activation gate

Require the plaintext rejection, failed TLS handshake for a test-only certificate and socket cleanup. Upstream admits plaintext WebSockets for onion destinations over its bundled Tor client. The service and peer Arti clients use the public Tor network for directory, introduction and rendezvous traffic. The application relay and artifacts stay test-owned, and no public application relay is configured. The test does not use Tor exit traffic. The onion address and keys remain within the private test workspace. Relay startup evidence establishes local service construction. Only active upstream owners provide positive evidence of successful authenticated transport activation.

It provisions distinct explicit file-backed disposable credentials and checks the ready manifests and permissions. A test-owned onion relay is the only configured endpoint. The receipt carries sanitized stages, checks and digests. Cleanup tests require the directory and process groups to disappear on success, injected failure, timeout and interruption. The live oracle needs additional evidence of relay admission restricted to the test principals, authenticated fixture execution, exact foreground and detached outputs and cold/warm results. An activation pass by itself does not freeze a command oracle.
