# Bounded owner preparation

The [workspace](../../../oddlang/portable/workspace-bounded-owner-prepare.json) adds the [prepare contract binding](../../../oddlang/portable/bounded-owner-prepare-v1/foreground.json) to the composed owner. The daemon uses the same framed private Unix socket for status and prepare. Prepare applies to the client role and the configured trusted peer on the configured relay. The workspace binds one peer, one onion relay, one room slot and a bounded preparation turn.

Prepare starts with `local_busy`. The owner obtains a signed key package for the authorized peer, fences the selected room before native creation, and records the group and session before publication. A `ready` reply follows local acknowledgement of the persisted Welcome on the selected relay. A cold owner validates the retained group and transport binding before reusing a ready session. An interrupted or inconsistent binding fails closed with a finite category.

The [fixture](prepare_room.py) binds a generated client owner and the pinned upstream server owner to a test-owned relay. It checks trust and relay refusals before production of a room, verifies actual placement in the generated account journal, separately verifies the matching admission in the upstream journal, and checks duplicate requests and a cold restart. The fixture sends no application commands. The [journal probe](prepare_journal_fixture.c) reads the disposable journals and receives the derived fixture key over stdin. After owned shutdown it resets only the isolated client's ready flag to reproduce a lost application commit after native acknowledgement. The final standby check requires the same session and upstream admission after restart.

Run the fixture with an artifact directory, the pinned reference binary directory, the pinned Deaddrop binary, the journal probe and an unused receipt path. Supply the three executable digests shown by `prepare_room.py --help`. Build the C probe on macOS with the linked reference build's SQLCipher and OpenSSL static archives, `-lz -framework Security -framework CoreFoundation`, and the pinned toolchain.

The [warm native preview](bounded-owner-prepare-warm-preview-aarch64-apple-darwin.json) uses compiler `fadd16875f402e9e1979335a94b31be1dd25e0ac` and portable inputs `8b38f38996b707df9cf6519f1f58a3b0d45b1339`. It records observed application placement, separate upstream admission, retry after unavailable discovery, duplicate prepare and the simulated acknowledgement boundary. A withdrawn or inconsistent native Welcome returns the typed uncertain outcome and the owner retains the original fence for that binding.

The [cold source-denied build](bounded-owner-prepare-build-aarch64-apple-darwin.json) passed the [independent network-denied preflight](bounded-owner-prepare-preflight-aarch64-apple-darwin.json). The [first mixed foreground probe](bounded-prepare-mixed-foreground-generated-client-upstream-server-macos-arm64.json) used those exact artifacts. Both owners activated and cleanup passed. The generated CLI exited 255 with `marmish: command_local_response` after 2.069 seconds and the receiver produced no command fixture receipt. The generated owner accepts prepare while the next local submit operation has no corresponding handler.
